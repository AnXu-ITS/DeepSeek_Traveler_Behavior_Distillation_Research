# Official API provenance and retrospective cost estimate

This 25 September 2026 revision uses existing records only. It makes no new Teacher calls and does not reconstruct a provider invoice.

## Model and provider

The authors confirm that Teacher elicitation throughout the study used **DeepSeek V4 Pro supplied by the official DeepSeek API**, at `https://api.deepseek.com`, with model `deepseek-v4-pro`. All 3,242 retained response records that contain a model field in the inspected later campaigns and latency experiment return that name. Early repeat archives do not retain that field; their service attribution is author-confirmed rather than independently recovered from each response.

The [current model table](https://api-docs.deepseek.com/quick_start/pricing/) identifies V4-Pro-0813. The [updated official change log](https://api-docs.deepseek.com/updates/) explicitly confirms continued Pro service after 14 September. The older [news announcement](https://www.deepseek.com/en/news/deepseek-v4-1-flash/) still describes a conflicting routing plan. The revised paper uses the updated API notice and the authors' records; it does not infer that the experiment used Flash. Service identity does not establish an immutable backend fingerprint for every response.

Primary supervision completion creation times span 21–27 August 2026 UTC. The final accessibility-aware, neutral-metadata, ownership-matched survey campaign spans **21 September 2026, 16:35:54–17:01:40 UTC**. Selection seed `20260921` is not a request timestamp. All 1,440 metered final-campaign requests record `max_tokens=16384`; the copied summary configuration says 8192, so the request-level fields take precedence. Frozen configs are preserved as historical evidence, with this discrepancy documented explicitly.

## What the estimate includes

The [aggregate ledger](../evidence/revision_20260925/api_usage_aggregate.json) records source-file hashes, counts, missingness, model-field coverage and token totals. No participant-level request or response payload is added. The [CSV](../evidence/revision_20260925/api_cost_table.csv) and [machine-readable estimate](../evidence/revision_20260925/cost_estimates.json) are generated by an offline script.

| Retained group | Metered completions | USD, off-peak–peak |
|---|---:|---:|
| Primary supervision archives | 8,681 | 65.83–131.66 |
| Final same-task reference | 1,440 | 7.08–14.16 |
| Earlier same-task campaign | 1,475 | 11.58–23.15 |
| Two metadata/ownership pilots | 240 | 1.03–2.07 |
| Latency experiment | 87 | 0.76–1.51 |
| Other historical development, including deprecated S8 | 1,468 | 16.43–32.86 |
| **Deduplicated metered total** | **13,391** | **102.71–205.42** |

The total comprises 17,156,526 input and 50,418,339 output tokens. A further **576 distinct completions have no usage record**. They are not priced as zero. Primary supervision pools contain acquired labels beyond the final benchmark subset; the total is not the acquisition cost of one final Student. Historical S8 expenditure remains development expenditure, not valid S9 evidence.

The USD rates per million tokens are 0.044 cached input, 1.32 uncached input and 3.96 output at peak; off-peak is half. The [official CNY rates](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) independently give CNY **700.30–1,400.61** for the same usage (0.30/9/27 peak). This is not an exchange-rate conversion. Rates were checked on 25 September 2026. The endpoints are tariff scenarios, not confidence bounds or the exact deductions at historical request times.

Deduplication is by completion ID across superset archives. Reasoning tokens are already included in completion tokens. The earlier generic-prompt campaign has 35 parse-rejected but metered responses; their tokens remain included. HTTP failures without usage are counted in the source ledger but not assigned invented charges. Credits, promotions, taxes and missing sources are not reconstructed.

## What existing measurements can answer

Existing frozen data support acquisition-token estimates, post-training inference timing, supply-cache comparisons and recorded fit-time summaries. The 12 controlled neural status files report 29.58–32.13 s per fit, totalling 371.09 s on the recorded CPU setup. This is a sum of fit durations, not campaign elapsed time or all development/SA adaptation cost.

For a fixed scenario workload, monetary break-even is `N* = C0 / (c_L - c_S)` when the denominator is positive. `C0` must include acquisition, retries, training and necessary adaptation; `c_L` and `c_S` must use the same workload, input preparation, caching and resource tariffs. Shared routing/supply work is handled consistently. Monetary, wall-clock and resource break-even are separate analyses. The current record does **not** establish a complete lifecycle break-even or paid invoice. No new API experiment is needed merely to publish the present bounded estimate.
